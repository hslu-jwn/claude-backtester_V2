- Importer `src/backtester/data/histdata.py`: reads year files (`DAT_MT_<SYM>_M1_<YYYY>.csv`, regex line 79),
  also inside zips; `--cache-dir` exists (line 459); writes one parquet per UTC day.
  Raw layout today: `data/raw/histdata/EURUSD/` holds zips 2015-2021 (~3.5 MB per year); GBPUSD mixes csv

## 2. Clock convention: a clock check IS needed

- `histdata_to_utc` (`histdata.py:416-445`): years 2015-2018 use America/New_York US DST (line 424);
  every other year uses the European-dates rule (rule = NY standard time, +1 h while Europe is on summer
  time). ARCHITECTURE.md:230 says it plainly: "Before 2015: existing European-date rule retained,
  unverified here". `results/clock_check_histdata.md` stops at 2015 (its closing line: "No pre-2015
  histdata available here"), and the MT5 clock proof dropped 2010-2014 because MT5 has no reference
  there (ROADMAP line 181). So the rule for 2008-2014 is a guess; the file clock flipped between 2018 and
  2019, so it may differ again earlier (possibly per year).
- Why it matters for F1a: entry 07:00 and exit 13:00 London (`research/grids/timed_hold_fx_eu.toml`).
  A wrong rule shifts all candles one hour in the US/EU mismatch weeks (about 3-4 weeks a year, 2 in March,
  1-2 around late Oct/early Nov) - small but it biases the exact window the hypothesis is about; and a
  fixed-EST file (the FAQ's claim) would shift the whole summer by one hour.
- How (no MT5 needed, same method as `scripts/v26b_clock_evidence.py`): import 2008-2014 once under the
  current rule into the separate pre-sample cache, then measure per year, in New York time, the Friday last
  bar + 1 min and the Sunday first bar (FX anchor: Sunday 17:00 NY open, Friday 17:00 NY close) for every
  US/EU gap week plus January/July normal weeks. Decision per year: `{17:00}` in both gap and normal weeks =
  rule correct; `18:00` in gap weeks = US-DST rule needed. Corroboration without a reference feed: the
  8:30 NY NFP spike (first Fridays) and 14:00 NY FOMC days in the EURUSD data (the 2015-2018 check used
  FOMC days the same way, strategy-timed-hold.md:123). Write `results/clock_check_histdata_pre2015.md`
  BEFORE any strategy run (measure first, then fix, as for V2.6b).
- If a year needs the US rule: change the hard-coded `between(2015, 2018)` (line 424) into a small table
  of year ranges; re-import only the pre-sample cache. Existing 2015-2021 cache is untouched.

## 3. Side effects and the safest isolation

Problem confirmed: `_run_research_locked` takes `first, last = cached_span(spec.symbols, sources)`
(`research.py:764`, `cached_span` lines 158-171) and uses `first` as dev start (line 770, stored line 784).
Importing 2008-2014 into `data/cache/histdata/` would silently move the dev start of every grid, change
`grid_id` comparisons/halves/DSR of all earlier research, and also feed every tool that reads
`DEFAULT_SOURCES` (`cached_days`, e.g. open_gap_study, noise_study, mt5_clock_check, cache repair). A later
`python -m backtester.data.histdata data/raw/histdata/` would also import anything lying under that folder.

Recommended (nothing touches the main cache, no change to the dev/test split):
1. Separate raw root `data/raw/histdata_presample/` (NOT under `data/raw/histdata/`) and separate cache
   `data/cache/histdata_presample/` (same layout; `importer --cache-dir`, `downloader --root` both exist).
2. Run the strategy through `run_research(..., sources=SymbolSources.single(PRESAMPLE_DIR, symbols))`:
   `run_research` already has a `sources` parameter (line 707) that reaches `run_backtests` via
   `run_period`/`run_variant` (research_helpers.py:33-41). Only the CLI lacks it (`parse_args`, lines 1400-1419,
   no `--cache-dir`).
3. Separate results dir: `--results-dir results/presample_2008_2014` (hidden flag, line 1418). Needed because
   `grid_id(spec, variants)` depends on the grid file only, so the same F1a grid would collide with the existing
   folder (refusal without `--retest`, line 1134), and because `TRIALS_FILE` lives in `results_dir`, keeping
   the main trial log (DSR N) clean. Record the pre-sample as a separate, pre-registered check in the research log.
4. The test period stays unspent by construction: the cache ends 2014-12-31 < cutoff 2021-09-14, so
   `dev_end = min(cutoff-1, last)` (line 765) and the test step reports "no cached data from cutoff: no test
   run" (line 1161). Pass `--dev-only` anyway (belt and braces).
5. Gates: `timed_hold_gates` builds its sources from the saved run's `cache_dirs` (`timed_hold_gates.py:214`,
   written by `runner.py:788`), so it reads the pre-sample cache automatically.

Minimal code change: add `--cache-dir PATH` to `research.py` `parse_args`/`main` and pass
`sources=SymbolSources.single(args.cache_dir, <grid symbols>)`. Symbols come from the grid, so the
single-folder form needs them after `load_grid` - simplest is to build it inside `main` from
`load_grid(args.grid).symbols`, or let `run_research` accept `cache_dir`. About 10 lines. Alternative with
zero code change: call `run_research(..., sources=...)` from a one-off Python snippet in the scratchpad.

Known limits to state in the report (not blockers):
- Costs: the spread table fills years without a measurement from the nearest measured year
  (research-runner.md:129-133), so 2008-2014 uses 2021 spreads; real 2008-2014 EURUSD spreads were wider, so
  results are optimistic on cost. Run gate 1 (doubled costs) and report it.
- Bid-only data, no ask (`histdata.py:34`), same as the development data.
- 2008-2009 is a crisis regime; judge by sign and magnitude vs the 0.042 R/trade net, not by significance
  alone. Pre-register the pass rule before looking: EURUSD short net R per trade > 0 and both halves > 0
  (2008-2011 / 2012-2014), as gates 1-3 in strategy-timed-hold.md:81-93.

   2008-01-01 and 2015-01-01 edge days are written only if complete (partial days are listed, lines 474-479).

   copy to the scratchpad): per-year table into `results/clock_check_histdata_pre2015.md`.
4. If the table shows US DST for some years: change `histdata_to_utc` (test first, see 5), delete
   `data/cache/histdata_presample`, re-run step 2, re-check.
5. Add `--cache-dir` to the research CLI (test first), then:
   `python -m backtester.tools.research research/grids/timed_hold_fx_eu.toml --dev-only --cache-dir data/cache/histdata_presample --results-dir results/presample_2008_2014`

7. Report in `knowledge/research/reports/`, log in `docs/research-log.md`; no change to defaults, DEFAULT_SOURCES
   or the main cache. Confirm afterwards that `data/cache/histdata/` is byte-identical in day count
