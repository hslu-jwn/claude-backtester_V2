# Brief: V2.4e economic calendar — built on synthetic data (night 2026-10-26/27)

Context: ROADMAP › V2.4e (full description, decisions of the user 2026-10-26) and the
instructions in `../backtester-news/implementation_instructions.md` (read both fully; also
`../backtester-news/verification_2026-10-26.md`). The delivered CSV has wrong timestamps and is
being regenerated by the user, so **tonight everything is built and tested on synthetic data
only**; no result, report or golden list may use the current CSV. Nothing changes a trading rule
or a default.

## Build

1. `src/backtester/data/news.py`: read-only loader with the explicit schema of the CSV (columns as
   in the file header), UTC-aware parsing, blank timestamps stay blank, validation (unique
   `event_id` / `dedupe_key`, impact only High / Medium, exact rows (`minute` / `second`) must
   parse, range rows need both window ends), sha256 of the file returned with the calendar.
   **Extra checks from Opus's verification** (warnings with counts, configurable to errors): exact
   rows whose `time_label` is `00:00:00` or `23:59:59` (lost / all-day times labelled exact);
   rows on Saturday / Sunday UTC; source-boundary composition changes (High count per source and
   year). Path from settings (default `data/news/economic_events.csv`, git-ignored, absent ->
   the feature reports "no calendar" and stays off).
2. Instrument -> currencies mapping in config (XAUUSD, GBPUSD, GBPJPY, NAS100, US500, US30,
   US2000, GER40, EURUSD, ...; `GLOBAL` decided per instrument, default off), `currency` first,
   `country` second.
3. Schedule and results behind separate interfaces: strategies get schedule-only events (no
   `actual` / `forecast` / `previous` objects at all); a separate result accessor returns
   `actual` only at `release + delay` (setting) and is not wired to any strategy.
4. **News-day split** in the research runner (like the shock-day check): per variant, results on
   days / minutes with High-impact events of the traded instrument's currencies vs without; only
   from 2020-01-02 (earlier trades reported apart as "no calendar", never counted as news-free);
   rows per source period reported apart when a source boundary changes the coverage (setting).
   Off when there is no calendar file.
5. **Blackout filter** as an engine / strategy-runner setting, default **off**: windows before /
   after per impact (settings, minutes), policy block entries / flag only, date / range /
   unknown rows by a separate conservative policy (block the day / skip with warning),
   simultaneous events kept. Pure function `blocked(t, instrument, calendar, config)` +
   wiring where orders are accepted (reuse the existing order-skip path and its counters).
6. Tests (synthetic CSVs in `tests/data/news/` built in the tests): every test in the
   instructions' "Minimum tests" list, plus the extra checks of 1, the split's "no calendar"
   bucket, filter default off = identical trades (golden lists unchanged), filter on blocks an
   order exactly inside the window and allows one just outside (inclusive / exclusive rule
   documented), no look-ahead (`actual` unavailable one tick before release + delay).
7. Docs: `docs/news.md` (new) with the rules above; ROADMAP V2.4e status line.
